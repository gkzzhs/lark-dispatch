# 用户反馈采集模板

> 用途：第三周期补充真实用户验证，证明 lark-dispatch 不只是能跑，而且确实减少会后整理和信息分发成本。

## 一、邀请话术

可以直接发给 PM、组长或经常组织会议的同学：

```text
我在做飞书 AI 校园挑战赛项目 lark-dispatch，想请你花 5 分钟看一个会后分发 Demo。

它解决的问题是：会议纪要生成后，待办、决策、知识点经常没人看、没人跟进。Demo 会展示 AI 如何从纪要中提取待办/决策/知识，经确认后创建任务、推送决策、沉淀知识库。

看完后想请你回答 5 个很短的问题，用来验证这个工具是否真的能减少会后整理成本。
```

## 二、反馈问题

| 问题 | 记录 |
|------|------|
| 你的角色是？（PM/组长/研发/运营/其他） |  |
| 你每周大概参加或组织几场会议？ |  |
| 你现在会后整理待办/决策通常花多久？ |  |
| 看完 Demo 后，你觉得它最有价值的点是什么？ |  |
| 哪个环节你会担心或不信任？ |  |
| 如果在你的团队使用，你是否愿意试一次？为什么？ |  |
| 你认为它相比“把纪要链接丢群里”有没有提升？ |  |
| 你愿意给它打几分？（1-5） |  |
| 可引用原话（需征得对方同意） |  |

## 三、建议记录格式

| 用户 | 角色 | 会议频率 | 当前痛点 | 认可点 | 担心点 | 愿意试用 | 评分 |
|------|------|----------|----------|--------|--------|----------|------|
| U1 | PM | 每周 5-10 场 | 会后手动建任务耗时 | 待办自动进任务 | AI 提取是否准确 | 是 | 4/5 |
| U2 | 组长 | 每周 3-5 场 | 决策同步容易漏人 | 按人分发 | 需要确认门控 | 是 | 4/5 |

## 四、效果报告写法

收集到 2-3 个反馈后，可以在效果验证报告中新增一节：

```markdown
### 用户反馈验证

本轮邀请 3 位目标用户观看 lark-dispatch 会后分发 Demo，其中包括 2 位经常组织会议的 PM/组长和 1 位参会成员。

| 指标 | 结果 |
|------|------|
| 愿意试用 | x/3 |
| 认为相比“群里丢纪要链接”有提升 | x/3 |
| 平均评分 | x/5 |
| 主要认可点 | 自动创建任务、决策定向通知、分发报告可追溯 |
| 主要担心点 | AI 提取准确性、误推送风险 |

针对担心点，lark-dispatch 采用“先确认后执行”的门控设计，所有任务创建、消息推送和知识库写入都必须经用户确认后执行。
```

## 五、注意事项

- 不要把用户姓名、手机号、open_id 等个人信息写进公开仓库。
- 可公开材料里只写匿名用户编号，如 U1、U2、U3。
- 如果引用原话，先征得对方同意，并去掉敏感项目名。
- 反馈重点不是“夸项目”，而是证明是否解决真实会后分发痛点。
