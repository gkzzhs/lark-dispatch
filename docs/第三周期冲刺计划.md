## 二、会议给出的产品口径

本次分享对项目冲刺的启发很明确：不要继续堆功能，要证明小切口解决了真实痛点。

| 会议口径 | lark-dispatch 对应动作 |
|---------|------------------------|
| 选一个小切口，解决真实痛点 | 聚焦“会后纪要没人看、待办没人接、知识不流转” |
| 一句话讲清楚产品，说人话 | 主表达固定为“开完会，AI 自动把待办、决策、知识分给该知道的人” |
| 有真实用户验证更有说服力 | 补 2-3 个 PM / 组长 / 参会成员反馈 |
| 需求是否值得做要充分论证 | 前置“通用搜索/问答为什么不够”的对比 |
| 找不同的人体验作品 | 做一次 5 分钟 Demo 试用与反馈采集 |
| 不要卡 DDL | 2026-05-02 前完成核心证据链，后续只包装 |

## 三、第三周期目标

### P0：必须完成

1. **真实 cron E2E 主动触发证据**
   - 目标：从 OpenClaw cron 触发到生成确认草稿，留下 `cron runs` 记录。
   - 证据：任务配置、run history、确认草稿截图或文本、无静默分发说明。
   - 成功标准：能证明主动触发不是只停留在参数验证。

2. **IM 向他人推送验证**
   - 目标：找同租户测试用户或测试群，完成一次决策消息推送。
   - 证据：命令输出、消息截图、分发报告中的状态记录。
   - 成功标准：补齐“通知发到相关人”这一链路，不再只靠跨租户降级说明。

3. **真实用户反馈**
   - 目标：至少 2 个目标用户看 Demo 或试用。
   - 证据：反馈表、原话摘要、是否愿意在团队会议中使用。
   - 成功标准：把用户接受度从“任务完成率”扩展到“真实用户认可”。

### P1：强烈建议完成

1. **演示主线收敛**
   - 输入：一场会议纪要。
   - 过程：AI 提取 → 用户确认 → 创建任务 / 推送决策 / 沉淀知识。
   - 输出：分发报告。
   - 原则：只展示一条主线，不展示批量会议、自定义规则等边角能力。

2. **评测用例表**
   - 把三场会议按“待办/决策/知识/人员解析/分发动作/证据链接”整理成一张表。
   - 等 2026-04-30 评分标准出来后补对应字段。

3. **提交材料对齐**
   - 2026-04-30 19:00 后第一时间对照官方清单。
   - 不新增大功能，只补文档结构、链接、截图和演示说明。

### P2：暂缓

- 多会议批量处理
- 自定义分发规则
- 复杂置信度评分
- 多维表格完整归档

这些功能有价值，但当前阶段容易稀释“小切口、真实痛点、证据充分”的比赛叙事。
