# 评审快速入口

本文档用于快速复测 lark-dispatch 当前能力，并区分已验证能力、非破坏性验证路径和仍需用户确认的真实分发动作。

## 当前结论

lark-dispatch 已验证可以完成：

| 能力 | 当前状态 | 说明 |
|---|---|---|
| 飞书妙记读取 | 已验证 | `vc +notes` 可读取真实妙记；在线 AI 产物不足时使用逐字稿 fallback |
| AI 提取确认草稿 | 已验证 | 可从纪要/逐字稿提取待办、决策、知识点，并进入确认门控 |
| 人员解析 | 已验证但需确认 | `contact +search-user` 可返回候选；同名、多候选、未命中均需在确认草稿中标注 |
| 任务/文档/知识库/消息 | 真实闭环已验证 | 2026-05-10 已完成真实任务、知识文档、分发报告和 bot IM；后续真实写入仍必须等待用户确认 |
| OpenClaw 主动触发入口 | 已验证到确认草稿 | cron 可创建、运行、追踪；不应写成“自动完成真实分发” |

## 真实实测建议

当前已完成最小真实闭环实测。后续复测时，本地检查和非破坏性验收通过后，由用户明确回复“开始真实最小闭环实测”即可进入；真实写入前还需要第二次确认，执行步骤见 `docs/真实实测Runbook.md`。

## 一键本地复测

```bash
cd lark-dispatch
bash scripts/check-docs.sh
bash scripts/check-docs-api.sh
bash scripts/smoke-test.sh
```

`check-docs.sh` 检查文档、示例和安全口径是否一致；`check-docs-api.sh` dry-run 验证飞书 docs v1/v2 参数形态；`smoke-test.sh` 只执行只读检查和 `--dry-run` 写入预览，不会创建真实飞书任务、文档、知识库节点或消息。

如果样例妙记 token 不在当前账号权限内：

```bash
LARK_DISPATCH_SMOKE_MINUTE_TOKEN="<minute_token>" bash scripts/smoke-test.sh
```

## 复测口径

- “无启用 cron”以 `openclaw cron list` 为准。
- “存在历史记录”以 `openclaw cron list --all` 为准。历史 disabled 任务不代表仍会触发。
- “可写入”优先用 `--dry-run` 验证请求结构；真实创建任务、发送消息、写文档必须等待用户明确确认。
- “真实实测”需要两次确认：第一次进入真实会议处理，第二次才执行真实写入。
- “重复分发防护”要求在真实执行前先查 `docs/assets/live-runs.jsonl`，再搜索同会议标题或妙记 token 的历史分发报告；命中后必须让用户确认是否继续。
- “报告创建顺序”要求先创建任务和知识文档，最后创建分发报告；遇到 `folder locked` 只做一次短重试。
- “docs API 迁移”要求 v1 使用 `--title --markdown --mode`，v2 使用 `--content --doc-format markdown --command`；本机已补测 docs v2 真实创建和 overwrite 更新成功，迁移前仍先跑 `scripts/check-docs-api.sh`。
- “bot IM 成功”需要开发者后台 bot 消息权限和会话条件；本机已补测成功，缺失时仍降级为分发报告记录。
- 在线 `vc +notes` 可能只返回 summary；若 `chapters/todos` 缺失，应读取逐字稿进行提取，并在确认草稿里标注“基于逐字稿”。

## 已知边界

1. 跨租户或未聊天用户可能无法解析 open_id，流程应继续生成文档/报告，并把未解析项列为跳过或待指定。
2. 同名候选不能自动选择，必须让用户在确认门控中指定。
3. 飞书 self-send 可能失败，不能把该限制记录为 Skill bug。
4. OpenClaw cron 当前只证明主动触发入口和确认草稿生成，不证明无人值守真实分发。
5. 本项目的 `skills/lark-dispatch` 依赖官方飞书 Skills；新环境需要先运行 `npx skills add https://github.com/larksuite/cli -y -g`。
