## 四、已知局限与改进方向

### 4.1 当前局限

| 局限 | 原因 | 影响 |
|------|------|------|
| 跨租户人员无法解析 | 飞书通讯录搜索限于同租户 | 公开会议场景下分发覆盖率受限 |
| 消息推送依赖 Bot 配置 | 需在开发者后台配置 Bot 能力 | 未配置时降级为仅创建任务 + 知识沉淀 |
| 单场会议验证 | 测试样本量有限 | 准确率数据需更多场景验证 |
| AI 提取依赖纪要质量 | 飞书 AI 总结质量直接影响提取效果 | 低质量纪要可能导致提取偏差 |

### 4.2 改进方向

| 方向 | 预期效果 |
|------|---------|
| 支持用户自定义分发规则 | 适配不同团队的分发偏好 |
| 增加分发前 AI 置信度评分 | 让用户优先确认低置信度条目 |
| 支持批量会议处理 | 一次性分发多场会议的信息 |
| 接入待办完成追踪 | 下次会议前自动检查分发的待办是否执行（与 lark-retro 联动） |
| 扩展到项目交接场景 | 从单次会后分发扩展为项目全周期知识管理 |

## 五、lark-cli v1.0.13 新能力适配验证

> 测试日期：2026-04-16 | lark-cli v1.0.13

### 5.1 新能力验证矩阵

| 新能力 | 命令 | 测试结果 | 所需授权 | 对 lark-dispatch 的影响 |
|--------|------|---------|---------|----------------------|
| 知识库节点自动授权 | `wiki +node-create` | ✅ 通过 | `--domain wiki` | **直接解决痛点**：之前创建的知识节点用户可能无权限查看，现在自动授权 |
| 创建云空间文件夹 | `drive +create-folder` | ✅ 通过 | `--domain docs` | 分发报告可归档到指定文件夹，支持按月/按项目分类 |
| user 身份发送富媒体消息 | `im +messages-send --as user` | ✅ 命令可用 | user 身份默认 | 决策通知可附带会议截图或相关文件 |

### 5.2 实测记录

**测试 1：文件夹创建**
```
$ lark-cli drive +create-folder --name "lark-dispatch 测试归档"
→ ok: true, folder_token: Hm3ufNu0GlK67ldMD0xcPBFCn7b ✅
```

**测试 2：知识库节点 + 自动授权**
```

→ ok: true, node_token: JiQJwDeTDiUPdgkI1EHcAkTnn2c ✅
→ 创建后用户身份可直接访问，无需手动授权
```

### 5.3 已知边界与限制

| 能力 | 已知限制 | 降级策略 |
|------|---------|---------|
| 知识库自动授权 | 仅限应用创建的节点自动授权；手动创建的节点不受影响 | 授权失败时在分发报告中标注，提示用户手动共享 |
| 文件夹创建 | 需要对目标文件夹有写入权限；根目录默认可写 | 权限不足时降级为不归档，报告仍正常生成 |
| user 身份富媒体消息 | 仅支持向已有会话的用户发送；文件大小受飞书限制 | 发送失败时降级为纯文本消息；仍失败则跳过推送 |
| `drive +create-folder` | `--folder-token` 为空时默认创建在根目录 | SKILL.md 中建议用户首次使用时指定归档目录 |

### 5.4 版本兼容性说明

| 版本 | 状态 |
|------|------|
| lark-cli < 1.0.13 | 基础分发功能正常；`drive +create-folder` 不可用，知识库需手动授权 |
| lark-cli >= 1.0.13 | **推荐**。全功能可用，知识库自动授权，支持归档文件夹 |
